# Game and interactive product journeys

Use the same experience profiles and evidence rules for browser, mobile and desktop games. Determine the playable build, core verbs, outcome goal, input method, save model and available tooling. Coordinator setup may inspect project instructions; a cold participant discovers controls and rules through the permitted surface. Do not silently load a guide or strategy into L0.

## Exercise a meaningful loop

Select only the relevant stages and state completion evidence before judging them:

| Stage | Observe through direct interaction |
|---|---|
| Boot and entry | First actionable screen, onboarding and route to play |
| Core verb | Move, aim, drag/release, choose, place, attack, confirm or the equivalent; visible response to normal input |
| One loop | A turn, puzzle, fight, lap, crafting action, wave or other meaningful unit |
| Outcome | Win/loss/partial objective, legible cause and actual resulting state |
| Settlement | Rewards/resources/progress in the promised destination; reopen when persistence is expected |
| Repeat/recover | Retry, next stage, pause/resume, saved return, supported reconnection |

Never substitute menu visits or simulated state changes for playing. If a full match is outside scope or time limits, report the completed loop and the untested final outcome. Do not require a win to call a loss/retry flow tested. Scripted seeds, checkpoints, accelerated time and debug controls can support setup or diagnosis, but must be labeled and cannot prove the ordinary progression path.

## Vary play by knowledge

- L0: use visible instructions, ordinary genre knowledge declared at setup and newly discovered controls. Do not inject a winning tactic or force random mistakes.
- L1: repeat known moves, reuse visibly learned rules and revisit the reward/save loop. Track whether repeated onboarding obstructs play.
- L2: use supported combinations, known efficient paths and relevant strategy; state the observed or seeded basis. Never infer perfect aim, reaction speed or hidden rules from the level label.
- Lapsed: check changed controls/rules and preserved progression with prior knowledge's build identified.

If L0 fails and an informed profile succeeds, inspect discovery, explanation and control feedback before attributing difficulty. If every profile fails, that alone still does not prove a balance defect. Check capability, rule understanding, reproducibility and expected behavior. Keep enjoyment, difficulty suitability and long-term retention as hypotheses unless suitable player/telemetry evidence exists.

## Match the tool to the claim

Record support for held/simultaneous keys, pointer lock, drag, touch gestures, controller, observation cadence and audio when relevant. A tool that cannot hold move and attack together cannot establish that the game prevents it. Distinguish tool latency, product response time and frame performance; do not infer human reaction times or input latency from an AI turn duration.

For Canvas/WebGL use inspected screenshots/video for visual claims; DOM text alone is insufficient. With screenshots off or unavailable, test permitted input/state properties and leave visual ones unverified. Source/state instrumentation may corroborate diagnosis but must not expose invisible targets to a cold participant. Do not claim sound quality from a fetched audio file or game score without listening evidence.

Use existing browser/device/native automation. Record desktop OS/window focus and actual input; mobile viewport emulation is not a physical-device test. Do not install an engine just to claim support. Missing tooling is an environment limitation, not a gameplay defect. Continue independent supported checks.

## Report

For each case give the profile, actual actions, mechanics used, outcome reached, recovery/retry and evidence. Separate product failures, discoverability/comprehension friction, tool limitations and proposed design changes. Reuse the seven-area taxonomy, mapping gameplay into functional, usability, recovery, persistence and performance areas rather than claiming all areas were covered.
