# app-qa-Human

[English](README.md) | [한국어](README.ko.md)

**앱·웹·게임을 초보자, 재방문 사용자, 숙련자 관점에서 직접 조작하고 증거가 있는 QA 보고서를 작성하는 AI 에이전트 스킬입니다.**

[기존 app-qa](https://github.com/Ddrubok/app-qa)를 유지하면서 별도로 설치하고 비교할 수 있습니다. 기존의 증거·재현 기준에 탐색형 QA, 테스트 케이스 생성, 버그 리포트 표준화, 스토어 심사 위험 점검을 추가했습니다.

스킬은 에이전트가 읽는 지침입니다. 실제 사람을 대상으로 한 사용자 조사나 자동 QA 서버가 아니며, 설치만으로 앱·회사 지식·협업 툴이 연결되지 않습니다.

## 경험 레벨과 직접 사용

QA의 증거 기준은 동일하게 유지하고, 제품에 대한 지식과 행동을 구분합니다. 한 AI가 학습을 이어가며 순차 실행할 수 있습니다. 독립적인 첫 사용자 검증은 대화·지식 분리가 확인되어야 하며 새 브라우저만으로 성립하지 않습니다. 기존 체크리스트의 지정 경로는 안내받은 검사로 유지합니다.

| 프로필 | 시작 지식 | 주요 확인점 |
|---|---|---|
| `L0` 첫 사용자 | 중립적인 목표와 화면에서 직접 배운 내용 | 시작 방법·용어·첫 작업 완료 |
| `L1` 재방문 사용자 | 이전 실행에서 배운 내용; 실패한 경험도 포함 | 알려진 작업 반복·저장 결과·이어하기 |
| `L2` 숙련 사용자 | 근거 있는 관련 숙련도 또는 명시한 사전 제공 지식 | 반복 작업·기능 조합·일관성 |
| `Lapsed` 변경 후 복귀 | 버전이 기록된 과거 지식 | 바뀐 UI·규칙 재학습·진행 복구 |
| `compare` 비교 실행 | 프로필마다 구분된 실행 기록 | 지식·시작 상태에 따른 차이 |

일반 QA의 기본값은 **요청 범위의 단일 실행과 간결한 Markdown 보고서**입니다. 목표·기대 결과, 실행·실제 결과, 증거, 남은 확인을 기록합니다. 경험 이력·캠페인 ID·7개 영역 표는 필수가 아닙니다. 관련 사전 지식이나 도움은 짧게 남기며, 기능 확인만으로 독립적인 첫 사용자 검증을 했다고 주장하지 않습니다.

```text
$app-qa-human 메모 저장과 다시 열기를 직접 QA해줘.
실제 결과·증거·미검증 범위를 간결하게 보고해줘.
```

발견 가능성·학습·경험 수준을 명시적으로 확인할 때 `profile=...`을 사용합니다. 에이전트가 읽는 요청 표현이며 셸 명령이나 실행 프로그램이 아닙니다. `mode=quick|full`은 보고서 깊이만 정하며 full만으로 여러 프로필을 실행하지 않습니다. 실행 횟수만으로 숙련자가 되거나, 제공받은 지식을 실제 사용 경험으로 바꾸지 않습니다. 비교가 필요할 때의 별도 예시는 다음과 같습니다.

```text
$app-qa-human profile=compare 이 제품을 직접 QA해줘.
첫 사용자·재방문·숙련자 관점에서 근거가 있는 수준까지 실행하고,
첫 시도·학습 내용·도움 여부·저장 상태를 보존한 Markdown 비교 보고서를 작성해줘.
```

```text
$app-qa-human profile=L0 이 게임의 핵심 플레이 한 사이클과 재시도를 직접 확인해줘.
조작과 목표를 발견하는 과정, 제품 문제와 입력 도구의 한계를 구분해줘.
```

첫 사용자 실행의 요구사항·이전 결함·정답 경로는 준비·판정 역할이 관리합니다. 사용자 역할에는 중립적인 목표와 허용된 정보만 전달하고, 기술 진단 전에 첫 시도와 학습을 보존합니다. 지식 분리가 안 되는 환경에서는 가능한 검사를 계속하되 사전 지식 있음/분리 미검증으로 표시합니다. 스크린샷 OFF를 우회하지 않으며 DOM 검사만으로 시각적 발견 가능성을 인증하지 않습니다. 작업 성공과 사용성 마찰도 별도로 보고합니다.

[프로필·지식 분리](references/experience-profiles.md), [반복 사용 이력](references/session-memory.md), [게임 진행](references/gameplay.md), [보고서 템플릿](templates/experience-report.md)을 참고하세요. [JSON 템플릿](templates/experience-run.json)은 미실행 예시입니다. 기존 schema 2.0과 실행 상태는 유지하며, 엄격한 기존 소비자에는 경험 정보를 연결된 별도 기록으로 제공합니다.

```sh
python scripts/validate_experience.py report.json --require-experience
python -m unittest discover -s tests -v
```

검사 도구는 경험 확장이 있는 보고서의 사례·결함 증거에서 null·공백·문자열이 아닌 항목·미등록 출처 ID를 거부합니다. 통과·실패 사례와 확인된 결함에는 등록된 증거가 필요합니다. 경험 확장이 없는 보고서는 명시적으로 검사를 건너뛰며 `--require-experience`를 지정하면 거부합니다. 기록의 일관성 검사이며 증거 파일의 존재·실제 실행·지식 분리·사용자 만족도를 인증하지 않습니다. 새 필수 런타임 의존성은 없고 XLSX 출력만 선택적으로 `openpyxl`을 사용합니다. [경험 레벨 검증 기준](references/experience-evaluation.md), [최초 개발 검증](evals/2026-11-10-experience.md), [증거 검사·기본 경로 보완 검증](evals/2026-11-10-hardening.md)에서 확인 범위와 한계를 구분합니다.

## 기존 체크리스트로 QA하기

프로젝트의 체크리스트와 검사할 빌드, 실행할 항목을 지정하세요. 사람이 작성한 목록도 사용할 수 있으며 `qa-checklist` 설치는 필수가 아닙니다. 원래 메모와 이전 결과를 보존하고, 구현 완료와 실제 검증 결과를 구분하며, 변경된 항목에는 재검증 필요 상태를 남깁니다. 근거가 부족한 체크 표시를 테스트 통과로 바꾸지 않습니다.

```text
$app-qa-human 테스트 빌드에서 docs/qa-checklist.md의 회원가입 항목을 실행해줘.
항목 ID와 이전 실행 이력을 보존하고, 실제 결과와 근거를 추가해줘.
```

목록을 수정하지 않으려면 보고서만 요청하세요. 체크리스트 준비만으로 실제 QA나 앱 코드 수정을 시작하지 않습니다. [연계 규칙](references/checklist-handoff.md)과 [유지보수용 회귀 사례](references/handoff-evaluation.md)를 참고하세요.

과거 기록: 2026-11-02 업로드에서 체크리스트 연계 지침을 반영했습니다. 아래의 2026-10-19 평가 결과는 더 이전 버전의 기록이며, 경험 레벨 확장의 검증 결과나 실제 QA 정확도 향상을 뜻하지 않습니다.

### 스크린샷: 기본 ON

실제 앱·웹 QA에서는 검사한 화면·케이스의 시작 상태와 결과를 촬영합니다. 정상 결과와 발견한 문제 모두 포함합니다. 이미지 뷰어가 있으면 저장한 이미지를 직접 확인하고 보고서에 연결합니다. 뷰어가 없으면 `Image file created (unverified visually by agent)`로 표시하고 가능한 DOM·텍스트 검사를 계속합니다. 이미지 저장 자체가 시각적 검증을 뜻하지는 않습니다.

```text
$app-qa-human screenshots=on 이 앱을 QA해주세요.
$app-qa-human screenshots=off 스크린샷을 찍지 않고 QA해주세요.
```

별도 옵션 없이 요청하면 ON입니다. “스크린샷 켜고”, “스크린샷 찍지 말고”라고 말해도 됩니다. 이 옵션은 에이전트에 전달하는 요청이며 셸 명령이 아닙니다.

OFF이면 자동으로 스크린샷을 찍는 도구도 사용하지 않고, 가능한 텍스트·DOM 기반 검사와 시각적 확인의 한계를 기록합니다. 같은 QA를 이어가는 동안에는 마지막 선택을 유지합니다. 별도 선호를 지정하지 않은 새 QA는 ON으로 시작합니다. 도중에 OFF로 바꿔도 이미 찍은 파일은 삭제하지 않습니다.

촬영 도구가 없거나 민감한 정보를 안전하게 제외할 수 없으면 누락 사유를 남깁니다. 촬영 계획만 세운 상태는 미실행으로 표시합니다. 기존 메모 정리·보고서 비교만 요청한 경우에는 새 앱 검사를 시작하거나 스크린샷을 만들지 않으며, 제공받은 이미지의 출처를 구분합니다.

JSON·엑셀 출력은 형식을 명시해서 요청하세요. 실제 XLSX 생성은 사용 가능한 도구가 필요하며 CSV를 엑셀 파일로 위장하지 않습니다.

## 보고서 깊이와 파일 출력

`mode=quick`은 기본값으로 간결하게 보고하고, `mode=full`은 상세 기록과 7개 영역의 확인 범위를 제공합니다. 보고서 길이를 정하는 옵션이며 필요한 검증을 줄이지 않습니다. 결함이 없다는 결과도 허용하며, 개수 제한 때문에 중요한 결함을 생략하지 않습니다. Markdown·JSON·XLSX 형식은 별도로 선택합니다.

```text
$app-qa-human mode=quick 회원가입과 오류 복구를 점검해줘.
$app-qa-human mode=full screenshots=off 기획서와 구현을 비교해줘.
```

TC와 결함 보고서는 Core·Extended 필드를 구분합니다. Severity는 영향도, 결함의 Priority는 수정 시급성, TC의 Priority는 실행 순서입니다. 중복 제출·작성 중 이탈·인터럽트·글자 확대·키보드 가림을 점검하는 참고표를 추가했습니다. Playwright·ADB·Maestro·Appium·iOS Simulator 실행 안내는 호스트가 제공하는 기능 안에서 사용합니다.

선택형 [XLSX 생성 도구](scripts/export_xlsx.py)는 Python과 사용 가능한 `openpyxl`이 필요하며 의존성을 자동 설치하지 않습니다. 문자열을 수식이 아닌 텍스트로 저장하고 저장 후 값과 파일 구조를 검사합니다. 너무 긴 셀이나 이미 존재하는 출력 경로는 조용히 데이터를 잃는 대신 거부합니다. [입력 형식과 사용법](references/cases-and-reports.md)을 참고하세요. CSV는 별도의 안전 처리가 필요하며 이 도구는 XLSX만 생성합니다.

## 업데이트 검증 — 2026-10-19

| 버전 | 1차 | 2차 | 판정 기준 충족 합계 |
|---|---:|---:|---:|
| 기존 로컬 버전 | 52/52 | 52/52 | 104/104 |
| 개선 비교 후보 | 52/52 | 52/52 | 104/104 |

기존 40개와 보완점을 겨냥한 새 사례 12개를 두 번 평가한 가상 상황 판단 시험입니다. 버전·반복마다 새 대화와 동일하게 상속된 모델·추론 설정을 사용했으며, 정확한 백엔드 모델 식별자는 확인할 수 없었습니다. 2차에서는 사례 순서를 뒤집었습니다. 실행 에이전트에게 정답을 제공하지 않았고, 별도의 AI 판정자가 버전명을 가린 답변을 고정된 기준으로 채점했습니다. 사람의 독립 채점은 수행하지 않았습니다. 한 실행의 사례들은 같은 대화를 공유하며 일부 내용이 겹칩니다.

이번 표본에서는 두 버전 모두 기준을 충족했습니다. **정확도 향상은 입증되지 않았습니다.** 실제 앱 정확도나 정밀도·재현율, 다른 모델에서의 신뢰성을 뜻하지 않습니다. 공정한 속도 비교도 수행하지 않았습니다.

비교 후 최종본의 `references/cases-and-reports.md`에 CSV 안전 지침 한 문단을 복원했습니다. 최종본에 대한 추가 XLSX·CSV 가상 판단 2개는 담당 에이전트 검토에서 기준을 충족했지만, 전체 비교를 최종 텍스트로 다시 실행한 것은 아닙니다. 변경하지 않은 XLSX 도구는 문자열·유니코드·길이 제한·잘못된 입력·기존 파일 보호·빈 보고서·CLI 저장 후 값 확인을 포함한 실제 실행 시험 9개를 통과했습니다. YAML·로컬 참조·Git 공백 검사도 통과했습니다. 실제 브라우저·기기 QA, Excel UI 동작, 이번 업데이트의 호스트별 활성화는 미검증입니다. [평가 지침](references/evaluation.md)과 확인 날짜가 기재된 [호환성 기록](COMPATIBILITY.md)을 참고하세요.

## 범위와 검증 상태

- 생성한 TC는 실행 결과가 아닙니다. 스크린샷만으로 조작·접근성 동작을 확인했다고 주장하지 않습니다.
- 심사 위험은 최신 공식 정책과 플랫폼·지역별 조건을 확인합니다. 승인 보장이나 거절 확률을 제공하지 않습니다.
- HIG·Material의 디자인 권장 사항을 곧바로 심사 거절 기준으로 취급하지 않습니다.
- QA 요청 자체는 코드 수정·배포·실제 결제·외부 메시지 전송을 허용하지 않습니다.
- Vector DB, Slack 봇, Jira 자동 댓글은 설치되어 있지 않습니다. 사용 가능한 자료와 도구를 활용하는 절차를 제공합니다.
- 파일 형식·참조 경로와 일부 가상 사례의 판단을 검토했습니다. 실제 앱 성능 시험이나 사람 대비 정확도 측정, 평가 목록 전체의 실행을 뜻하지 않습니다.
